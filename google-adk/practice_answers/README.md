# 练习参考实现

本目录存放各章「🧪 本章练习」的参考实现。**建议先自己写完，再打开对照**——直接读答案会跳过最有价值的那一段思考。

## 文件命名

`c<章号>_<题号>.py`，例如 `c7_3.py` 是第 7 章练习 3 的参考实现。

| 文件 | 对应 |
|---|---|
| `c1_1.py` | 第 1 章练习 1：改造第一个 Agent（学习计划助手） |
| `c1_2.py` | 第 1 章练习 2：事件观察器，逐条打印 author / is_final_response / 内容类型 |
| `c1_3.py` | 第 1 章练习 3：两用户三会话，断言会话隔离成立 |
| `c1_4.py` | 第 1 章练习 4：可复用对话入口（带 `--check` / `--demo` / 交互模式） |
| `c7_1.py` ~ `c7_5.py` | 第 7 章练习 1–5 |
| `c8_1.py` ~ `c8_5.py` | 第 8 章练习 1–5 |

> 第 1 章的练习 5 是纯思考题（推测同一程序改用 LangChain/LangGraph 会变成什么样），不需要编码，因此没有 `c1_5.py`。

## 运行方式

在仓库根目录执行 `uv sync`，并按仓库 README 配置好 `.env` 里的 `DEEPSEEK_API_KEY`，然后：

```powershell
# 第 1 章的练习是独立脚本，直接运行
uv run --env-file .env python google-adk/practice/c1_1.py

# c1_4 支持先自检再运行（--check 不需要密钥）
uv run python google-adk/practice/c1_4.py --check
uv run --env-file .env python google-adk/practice/c1_4.py --demo

# 第 7、8 章的练习复用 _common.py，需要从 practice 目录运行
cd google-adk/practice
uv run python c7_1.py
```

`_common.py` 放的是第 7、8 章 Notebook 里那几个辅助函数（`deepseek()` / `input_text()` / `collect()` / `start()`），抽出来避免每个练习文件重复一遍样板代码。

## 哪些练习会真实调用模型

| 文件 | 是否需要 `DEEPSEEK_API_KEY` | 说明 |
|---|---|---|
| `c1_1.py` | **需要** | 第 1 章的核心就是跑通真实模型 |
| `c1_2.py` | **需要** | 观察真实事件流，必须有模型回复 |
| `c1_3.py` | **需要** | 会话隔离要靠模型"记不记得住"来验证 |
| `c1_4.py` | **需要**（`--check` 除外） | `--check` 只做配置自检，可离线运行 |
| `c7_1.py` | 不需要 | 只验证编排与事件归属 |
| `c7_2.py` | 不需要 | 只观察事件流、`path` 与 `output_for` |
| `c7_3.py` | **需要** | 写作流水线，2 次模型调用 |
| `c7_4.py` | **需要** | 只有"需要修改"那条路径调用 1 次 |
| `c7_5.py` | 不需要 | 用 `asyncio.sleep` 验证并发上限 |
| `c8_1.py` | 不需要 | 人工确认的三条分支，用确定性输入 |
| `c8_2.py` | 不需要 | 审批摘要是纯函数，与模型无关 |
| `c8_3.py` | 不需要 | 数框架的默认重试次数 |
| `c8_4.py` | 不需要 | 用注入异常模拟模型故障，保持可复现 |
| `c8_5.py` | 不需要 | 用 SQLite 的 `UNIQUE` 约束模拟外部幂等键服务 |

> 💡 **不需要密钥的 8 个练习可以直接跑**（`cd google-adk/practice` 后 `uv run python c8_3.py`）。
> 这不是巧合，而是有意设计：**凡是能去掉模型抖动的地方，就去掉。**
> 并发上限、重试次数、幂等、审批摘要这些机制的正确性，本来就不该依赖"这次模型心情好不好"。
> 只有"模型真的能按 JSON 格式返回吗"这类问题，才值得花掉一次真实调用。

## 四点说明

1. **参考实现不是唯一答案。** 尤其第 7、8 章的题目都给了明确的**验收标准**，只要你的断言覆盖了那些标准，写法可以完全不同——甚至更好。
2. **断言比输出更重要。** 这些文件都以 `assert` 结尾而不是"打印一下看看"。练习的目的是学会把"我觉得对了"变成"我能证明它对了"，这正是第 7、8 两章反复强调的东西。
3. **写这类测试时，别盯着错误文案。** 框架会给节点异常套一层包装（`DynamicNodeFailError`），原始消息可能丢失。断言要盯**结构化字段**：哪个 id 失败、失败了几条、执行计数是几、版本号是几。
4. **先让错误"说人话"。** 看 `c1_4.py` 的 `ConfigError` / `ModelCallError`：缺密钥就说缺密钥、模型失败就带上会话名和原始异常。生产代码里，"报错报得清楚"和"跑得对"同样重要。
